# Why Luna sometimes skipped FeatureNetwork MCP — 2026-10-09

The synthetic coding trials configured a project-bound FeatureNetwork STDIO MCP server, but their ordinary task prompt said only to use a project dependency/impact tool **if available**. They did not install the FeatureNetwork host skill or lifecycle hooks in the agent checkouts. The configured arm also contained readable `network-spec/` YAML. A model could therefore solve or attempt the task through shell inspection without calling MCP.

The observed behavior varied. In the corrected GPT-6-Luna fanout series, the configured arm made 1, 0 and 0 MCP calls from Small to Large. GPT-5.6-Luna made 0, 0 and 0; its Medium run showed no observed network-file access. In the cross-package series, GPT-6-Luna made 0, 2 and 0 calls from two to eight flows. The eight-flow agent inspected network YAML through shell commands and reached 419/420 held-out checks. Sol called MCP in its configured trials. These are observed command and tool events, not proof of everything the model internally considered.

We checked server availability separately. The same medium fanout checkout accepted a direct SDK `network_impact` query with valid integrity and 41 impacted items; the CLI MCP listing showed the project-bound server enabled. In a fresh diagnostic checkout, GPT-6-Luna was explicitly instructed to call `network_impact`, follow continuation and avoid substituting shell YAML reads. It completed three successful `network_impact` tool calls and reported 42 returned feature IDs. That diagnostic used `direction: outgoing` with a broad text query even though generated relation edges point from dependent child to parent. **All 42 results had empty dependency paths**, including an unrelated seed item. It demonstrated tool availability and cursor continuation, but discovered zero profile-dependent paths. The diagnostic prompt SHA-256 was `c3b10c4f10de9fabcedf466276bcb704b649f259ee956de3543905584f2ae1a3`; the raw event log remains in temporary scratch outside the checkout. This establishes that the configured tool **can** be called by Luna under an explicit request. It does not establish the precise internal reason for any optional non-call.

The practical diagnosis is a discovery and selection gap in this benchmark integration: server registration alone did not consistently cause natural task use, and shell-readable YAML offered another route. Product behavior needs a separate live host trial with the actual skill/hook installation. To measure MCP's incremental value, preregister three arms on fresh paired seeds: code only, readable YAML without MCP, and readable YAML plus MCP. An explicit-tool diagnostic is useful for availability, but its stronger prompt must not be compared as though it were the same treatment as the natural coding prompt.
