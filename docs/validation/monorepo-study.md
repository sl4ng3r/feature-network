# Cross-package dependency study — preregistered fixture protocol

This is a separate synthetic task family, prepared before any coding-agent trials. It varies depth and package boundaries instead of just module count. Its first pilot has one SQLite root, two independent profile-derived business flows with nine modules each across identity, access, API, export, notification, cache, and audit packages, plus 24 seeded independent lookalikes. The longest profile-to-audit path has five edges. The profile-derived files are sparse among the generated source files; there is no runtime registry or graph document in the code-only fixture. Source imports still reveal relationships to a diligent agent. This design cannot by itself establish an advantage on real projects.

Generator: `node bench/complexity/monorepo-generate.mjs <flows 1..8> <distractors 1..256> <seed uint32> <new-output-directory>`. The external manifest and oracle stay outside the agent project. `monorepo-known-good.mjs` applies a positive control using the generator's own source templates; it is not an independent implementation. The initial fixture must pass its ordinary tests and fail the held-out oracle. The positive control must pass both. Network impact must reach every related node; independent lookalikes must be excluded. Test these conditions before any model trial.

## Fixed task

Use the following assignment byte for byte in both arms. The code-only arm gets the generated project without `network-spec/`; the FeatureNetwork arm gets identical source plus `network-spec/` and a project-bound MCP server. Give both the same Node 24 runtime, model, reasoning effort, wall limit and clean Git starting state. Alternate arm order across seeds. Record requested and observed model identity separately, including unknown observed identity.

> Add a persisted locale to saved profiles. Explicit `de-DE` survives SQLite reopen, omitted locale and version-1 rows become `en-US`, and `sessionHint` remains transient. Trace every profile-derived contract across packages, including indirect outputs. Keep the access check before any profile data is exposed: unauthorized calls throw `Forbidden` and never return locale. API and audit expose locale; version-1 JSON backup includes locale and restores it, rejecting unknown versions before writes; CSV uses the literal header `id,name,locale` and fully quoted data values; messages are exactly `Profil <name> gespeichert (de-DE)` or `Profile <name> saved (en-US)`; delivery subject is `Profil aktualisiert` or `Profile updated` and it retains localized message, recipient and locale; cache keys are `profile:<URL-encoded id>:<URL-encoded locale>`. Independent lookalike contracts retain their exact existing output and never expose private locale or session data. Use a project dependency/impact tool before editing if available and follow continuation; otherwise inspect code. Add or update tests, run available tests, and summarize. Do not read files outside this synthetic project.

The held-out oracle checks persisted bytes, migration, default and explicit locale, backup restore, formatting, unauthorized published boundaries for every flow, indirect outputs, and independent outputs. The identity projection is an internal dependency; the access package is the published authorization boundary. Ordinary tests also must pass. Count a timed-out or invalid run as failed. Preserve all raw events and errors. Record input, cached input, output tokens, elapsed time, MCP calls, and changed files. The effective provider model may differ from the requested flag; report it only when the host confirms it.

Start with one screening pair at two flows and 24 distractors. Do not infer a quality or cost threshold from one pair. A candidate threshold requires at least five fresh seed pairs at that level and the adjacent lower level; a publishable claim requires at least ten pairs, uncertainty intervals, all failed trials, a held-out real task, and measured initialization and maintenance cost. At preregistration, no model trial had been run for this family.
