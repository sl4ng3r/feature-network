# Progressive business fanout coding study (preregistered pilot)

This second task family answers the user's request to increase both the number of affected locations and the variety of business consequences. It remains a synthetic Node 24 SQLite app, not a real-application threshold. The earlier [projection sweep](reports/complexity-projections-2026-10-09.md) is a separate task family and is not pooled into this one.

| Level | Contract files | Profile-related files | Contract kinds | Indirect dependency depth | Seed |
| --- | ---: | ---: | ---: | ---: | ---: |
| Small | 24 | 12 | 5: API, backup/restore, CSV, message, audit | 1 | 44 |
| Medium | 64 | 40 | 7: Small plus notification and locale-sensitive cache key | 1 | 55 |
| Large | 128 | 96 | 9: Medium plus digest and backup/CSV bundle | 2 | 66 |

`bench/complexity/fanout-generate.mjs` shuffles related modules among independent lookalikes. The large digest reads message and audit outputs; the bundle reads backup and CSV outputs. These indirect paths execute at runtime and are represented by directed, evidenced network relationships. The code-only arm gets identical source and base tests but no network; the FeatureNetwork arm additionally gets the generated `network-spec/` and a project-bound MCP server. This intervention combines structured project memory and its query interface. It does not isolate the interface's contribution, and it does not include native hooks or automatic memory maintenance. A separate known-good implementation must pass every held-out check at each level before any agent runs.

The runtime registry itself exposes the dependency graph to both arms. This study tests whether the indexed network helps agents coordinate many diverse contract edits despite that source-level clue. It cannot establish a discovery advantage over code inspection, and its longest dependency path has only two edges. The external oracle evaluates outputs, not which graph the agent relied on.

## Fixed assignment

Use the same prompt byte for byte within every pair. The assignment is the same across levels; requirements for absent contract kinds are conditional. The details below are given to both agents so that a failed run measures implementation/discovery rather than guessing an undisclosed output format.

> Implement a persisted `locale` field for saved user profiles. An explicit `de-DE` must survive SQLite reopen; omitted locale and existing version-1 rows become `en-US`. `sessionHint` remains transient. Update every published contract derived from saved profiles, including indirect dependents, while independent lookalike records keep their current exact output and never publish private locale or session data. API and audit objects expose locale. JSON backup keeps `version: 1`, includes locale inside `profile`, and restore persists it. CSV keeps fully quoted values and changes its header to `id,name,locale`. Messages are exactly `Profil <name> gespeichert (de-DE)` for German and `Profile <name> saved (en-US)` for default English. Where notifications exist, German subject/body are `Profil aktualisiert` / `Aktualisiert: <name>`, English are `Profile updated` / `Updated: <name>`, and the object exposes locale. Where cache keys exist, use `profile:<URL-encoded id>:<URL-encoded locale>`. Where digests exist, preserve the localized message as `headline`, audit `actorId`, and locale. Where bundles exist, retain dependency backup payload and CSV bytes and expose locale from the backup's restored profile. Trace dependencies through at least eight steps; use a project dependency/impact tool before editing if available and follow any continuation, otherwise inspect code. Add/update tests, run available tests, and summarize your changes. Do not read files outside this synthetic project.

Run order is Small code-only then FeatureNetwork, Medium FeatureNetwork then code-only, Large code-only then FeatureNetwork. Codex CLI `0.162.0-alpha.17.2`, requested `gpt-6-sol` low effort, Node 24, fresh independent Git checkouts, and a 300-second per-run wall limit are fixed. The effective provider/model revision must be recorded when the host supplies it, not inferred from the requested flag. A timeout is a failed bounded run, and partial outputs are preserved for review.

The external `fanout-oracle.mjs` checks SQLite reopen/default/migration, exact outputs for every generated contract, actual backup→restore→SQLite roundtrip, escaped CSV, both locale branches, coupled outputs and independent private-field boundaries. Ordinary base tests must also pass. Agent statements and self-written tests are not the acceptance oracle. Host-reported input/cached/output tokens, elapsed time, observed MCP calls and changed files are collected separately; shell logs do not prove exhaustive source reads.

One paired run per level is screening only. A candidate quality crossover requires new paired seeds around that level (at least five more pairs at the candidate and adjacent smaller level). A candidate task-cost advantage with equal quality also needs repetition; do not infer one from a single pair. A publishable comparative statement requires at least ten fresh pairs around the claimed boundary, uncertainty intervals, an independent holdout task or application, exact model/host bindings, all failed trials, and measured or explicitly unknown setup/initialization/maintenance costs. If both arms pass or both fail at all levels, report no established advantage in the tested range and do not tune this fixture after seeing outcomes to manufacture one.
