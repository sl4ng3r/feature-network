# Connected memory: local measurement and independent acceptance

The primary criterion is complete held-out business and graph correctness. Token/time benefit is secondary. A faster run with missing consumer behavior fails. No actual model, native host installation or telemetry is launched by the scripts below. Actual host trials require a separately authorized synthetic installation.

## Filesystem benchmark

Run `npm run bench:connected` with Node 24. The declared matrix is 1/4/16 projects × 100/1,000 features per project × degree 2/12, five actual samples per phase. Temporary repositories contain only generated code/YAML and a synthetic connection register. Each feature has one source and exactly the declared edge count: local cyclic neighbors, with the first consumer edge linking the previous project's provider. The fixture, registry setup, external manual edits/restoration and cleanup are outside measured phases.

Phases are first network load, warm hint, fresh incoming impact, one document edit refresh, one source edit check, and grouped conversation maintenance. First-load samples use fresh option-bound parsing/index caches in an existing process: each sample has a distinct nonexistent exclusion root, matching no source. The OS page cache is uncontrolled. This measures fresh Core caches, not cold disk, process startup, complete plugin activation or MCP latency. The loaded-core benchmark remains a separate measurement.

Actual instrumented reads/bytes, YAML parses, shared digest calls, visits/index replacements, authoritative file publications/deletions, runtime publications and completed journal transactions accompany every wall-time sample. Metadata counters cover instrumented safe opens/file identity checks, not all OS syscalls inside path confinement. Read counters include registry/runtime/journal data. `knowledgeWrites` includes feature/marker files too. Source counters include fresh returned-feature checks and mandatory full end-state write validation; that technical work is not agent semantic analysis. Validation deduplicates identical source paths only within one fresh pass; writer guards remain fresh. Whole-process memory before/after is reported without a peak/allocation claim.

Requests use explicit maxProjects equal to the case's project count (16 for 16-project cases), maxVisitedFeatures 1,000, limit 20, budget 64,000 core-JSON bytes, incoming impact and depth 2. Returned source scope is the visible feature subset. Summary hints are last-known, fresh queries refresh consumers, and the response discloses partial coverage/limits. A separate test deliberately caps 16 roots at 8 and requires the remaining projects to be named. No complete application coverage claim follows from the matrix.

Each phase keeps every sample, median/p95/min/max, output bytes and counter/memory observations. Five samples yield a limited local p95 observation. The script binds the exact executed bundle SHA-256, nullable Git metadata and post-build source input hashes. Dirty-tree measurements remain explicitly dirty; they are not relabeled as immutable release evidence. Agent tokens, model latency and semantic source-analysis cost remain null because no agent/model work was performed. No token-saving estimate is presented as a measurement.

Unit tests run the smallest declared fixture with one sample and assert structural work properties rather than timing thresholds: zero warm parsing/source reads/writes, one index replacement for one document edit, measured source checks, one completed transaction/file publication for grouped statements, no fabricated review and zero no-op writes. The positive source-read assertion also guards against broken instrumentation silently turning work into zero.

## Scripted independent scenario

`tests/validation/connected-scenario.test.ts` creates provider A, consumer B and indirect consumer C in separate temporary roots. Its independent behavior oracle lives outside every candidate root and hard-codes published contract shape, private-field exclusion, entitlement decisions and denial presentation. It fails on the initial version and after only the provider is changed, then passes after the scripted consumer/view changes. Expected graph membership and the two-edge C path are checked independently of the query implementation.

The scenario also checks a newly added incoming edge after a warm hint, a discussion-only requirement with no fake source review, no-code-change semantic analysis with inspected hashes, interrupted target publication before progress acknowledgement, safe identical-intent resumption, an unavailable consumer and preserved manual points. Separate real SIGKILL/concurrency fixtures cover journal and progress interruption. This is scripted integration/fixture evidence; it does not measure whether a coding agent discovers or implements the change.

## Native host/model acceptance (pending)

Keep Codex Desktop, Copilot CLI and Copilot App as separate matrices. Freeze initial code, memory, task prompt and external oracle hashes; bind exact host/provider/model/plugin versions and source/bundle hashes. Use fresh sessions and at least three paired baseline/plugin trials per task; keep the oracle outside candidate roots and unavailable to the agent until evaluation. Pin the same model and reasoning settings in each pair. The baseline must have the same authorized repositories available, without FeatureNetwork guidance/tools. The plugin arm uses only the reviewed synthetic local register and explicit rights.

Tasks include a provider contract change requiring both direct and indirect consumer effects; an explicit discussion requirement; no-code-change source analysis; repeated identical discussion; contradiction/supersession; interrupted maintenance; and unavailable/denied target handling. Check all held-out behavior, privacy, manual-note and graph expectations. Require every expected check to run and pass; record error types and unexamined scope. Missing checks are incomplete, never success.

Collect actual tool events and provider usage evidence if available, without raw private prompts/source archives. Separate initialization, ordinary task and maintenance costs. Keep source reads, context bytes, elapsed time, actual measured tokens and unknown costs distinct. A configured MCP server is not proof of tool use; a passing scripted graph is not proof of model behavior. Without reliable usage data, measured tokens remain null. The existing comparison validator rejects synthetic records labeled as actual agent runs. Do not install a host, start agent sessions or publish a live report without the required concrete authorization.
