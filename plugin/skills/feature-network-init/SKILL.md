# Build or resume project memory

Start only for an explicit initialization request. A description match, missing marker or ordinary development task does not request whole-project analysis. Use the host agent's source tools and the five existing MCP tools; inputs have no project-root argument. Preserve existing features and manual key points. This command changes only network memory and local bootstrap progress, not product code, databases, host settings or Git commits.

1. Call `network_bootstrap` with `action:"status"` to show saved progress as `last_known`, then `action:"start"` to refresh the inventory and obtain the active package. Repeat invocation resumes existing work; never delete features to restart. A checkout/branch change requiring reconciliation needs explicit `start` with `reconcile:true`. Corrupt or unavailable state is a visible limitation. `.env.example` stays excluded unless the caller supplies a concrete sanitized-example attestation bound to its current hash; filename or user convenience is not such an attestation.
2. Work sequentially on the returned package, at most 20 slices and 65,536 planned UTF-8 bytes. Packages contain metadata only. Read the actual files through normal host tools using their inclusive line and half-open UTF-8 byte ranges; check actual source/full-file hashes against package metadata. Multiple slices of a large file require multiple packages; one read is not whole-file acknowledgment. Do not execute unknown project scripts just to inventory. If `packageOmitted:true`, retry within budget 64,000 or replan with smaller `maxFiles`/`maxBytes`; an omitted package is not an empty completed package.
3. Identify grounded features from inspected code, tests and documentation. Use `network_context` to obtain current full features and fingerprints, reassembling sections/fragments with `network_context({cursor: result.nextCursor})`. `nextCursor` is the response field; only `cursor` is the request field. Send no other selectors or budget beside it. Write focused `network_update` requests with the returned complete revision and expected feature fingerprints, actual inspected source hashes, and `decision:{outcome:"updated",reason:...}` or reasoned `"no_semantic_change"` when existing memory is still accurate. Initialize `_meta.yaml` plus the first real feature together with `initialize:true` and per-path `null` entries in the `expected` mapping, for example `{"network-spec/_meta.yaml":null,"network-spec/new-feature.yaml":null}`. Never send `expected:null`. Require `schema`, matching feature `id`, short `summary`, `key_points` and valid existing `code` references. Relations are directed `depends_on`, `reads` or `writes`: use `evidenced` only with a source, otherwise `hypothesis`. Leave unresolved analysis visible; never invent a feature for an empty/excluded project.
4. After network writes, fetch current context and collect saved feature fingerprints keyed by feature ID. Send `network_bootstrap` `action:"checkpoint"` with the raw returned `runRevision` as `expectedRunRevision`, active `packageId`, current `networkRevision`, exact unique package sources/full-file hashes, saved `featureFingerprints`, and exactly one `{path,startByte,endByte,featureIds,outcome,reason}` result per active slice. Result outcomes are `analyzed` or `needs_review`. Include every mapped association; do not invent hashes, slice bounds or receipt tokens. Network update and checkpoint are separate guarded operations: interruption or conflict acknowledges nothing; refresh state before retrying.
5. Call `next` and repeat. At the end, freshly review cross-area relationships. A package-free checkpoint requires `packageId:null`, empty `sources`/`results`, `relationalReviewComplete:true`, a concrete reason and every current saved feature fingerprint. Never reuse an old completion across changed revisions. Run the read-only full `network_check` and report remaining review items. Technical `completed` means acknowledged inventory and relationship review, while `coverage:partial` always remains; it does not prove complete domain understanding.
