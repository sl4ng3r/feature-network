# Reconcile selected memory with code

Use the current host agent and its normal source tools. Start with `network_check({mode:"full"})` and `network_context` to identify changed references and unknown change files. Narrow them by the user's description when supplied; sources with no trustworthy baseline stay uncertain and are analyzed only in the explicitly selected area. A missing network does not authorize whole-project bootstrap: report the gap and offer explicit `feature-network-init`. Do not absorb arbitrary backlog or rescan the whole repository.

1. Resolve the area through context summaries and inspect stored full features. Use bounded `network_impact` where necessary to identify related assertions/tests. Continue context or impact with only `{cursor: result.nextCursor}` in the respective tool call: `nextCursor` is a response property, `cursor` the request property. Collect all named sections or concatenate JSON fragments by UTF-16 offset through `total` and parse before treating a feature as complete.
2. Read the actual selected changed sources and only necessary dependencies/tests. Hash the sources actually inspected; explicitly verify absence for deleted sources. Compare meaning with the current memory. For growth, add grounded assertions or relationships; for shrinkage, remove claims and references shown to have disappeared. Preserve manual key points/user notes and unrelated concurrent work. A removed locale field, for example, can invalidate profile and backup/restore assertions while a user note remains intact. Evidenced relationships need sources; otherwise use `hypothesis`. Leave uncertain conclusions open rather than inventing content or a surviving reference.
3. Refresh current context before publication. Use complete proposed feature objects, the returned per-path fingerprint mapping as `expected`, and complete `expectedRevision`. A new path is a mapping entry such as `{"network-spec/new-feature.yaml":null}`, never `expected:null`. Call `network_update` with focused `upserts`/`deletes`, actual `verifiedReferences` for mapped inspected sources, and a concrete `decision.reason`. The only decision outcomes are `updated` when memory changed and `no_semantic_change` when inspection supports unchanged memory. Unmapped sources may be closed only by reasoned `no_semantic_change` in `observations`; they never receive baselines. An unchanged result needs no cosmetic YAML rewrite.
4. For a missing mapped source, first repair the network's obsolete reference/assertion using grounded surviving references, or remove a provably obsolete feature while preserving meaningful manual work. If safe repair is unclear, report it and leave review open. After repair, submit a separate reasoned `no_semantic_change` update with `observations:[{path,state:"missing"}]`, `expectedMissingReferences:[path]` and the current complete `expectedRevision`; no fake hash or baseline. The same guarded absence observation applies directly to an unmapped deletion. Keep current existing-source hashes and absent-source guards tied to actual observations.
5. A revision/fingerprint/source/absence conflict requires fresh context/check and renewed targeted inspection; preserve the other writer's data. Network mutation and semantic-decision publication are separate: interruption can leave the mutation applied and review open, so inspect state before retrying. Run `network_check({mode:"full"})` after publication and report remaining findings, omitted items and `coverage:partial`. The check itself confirms nothing; cache loss leaves semantic review open. Repeating sync without semantic changes should not rewrite YAML or create fake completion. This command changes memory and its review state, not product code or bootstrap checkpoints.
